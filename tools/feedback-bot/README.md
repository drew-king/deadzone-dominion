# Deadzone Dominion feedback bot

The owner’s Discord server is `1571630020420702280`. The feedback forum is `1571630824439283793`. Keep verification with a Roblox/Discord verification service approved by the owner. Give verified players access to submit feedback. Give Moderator permission to use the roadmap commands in the feedback forum. Discord roles and command visibility are separate from the server-side role and guild checks.

1. An owner creates a Discord application, adds its guild-scoped bot, and permits View Channel, Send Messages in Threads, and use of application commands in the feedback forum. No Administrator grant is required. Give the bot no access to DMs or the private staff channel. In Server Settings → Integrations, allow the Moderator role to use the three registered commands.
2. Create and install a GitHub App on the private `drew-king/deadzone-dominion` repository only. Grant Contents read/write and Pull Requests read/write. Protect the main branch and keep the bot outside any bypass list. The bot writes only one feedback file per thread on a branch and opens a PR.
3. Set `DISCORD_APPLICATION_ID`, `DISCORD_PUBLIC_KEY`, `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID`, `DISCORD_FEEDBACK_FORUM_ID`, `DISCORD_MODERATOR_ROLE_ID`, `GITHUB_REPOSITORY`, `GITHUB_APP_ID`, `GITHUB_INSTALLATION_ID`, `GITHUB_APP_KEY`, and `FEEDBACK_DB_PATH` in the host. Use secret storage. Run one Node 24+ process with a persistent SQLite volume. Terminate HTTPS at the host and set the Discord Interactions Endpoint URL to `https://your-host/discord/interactions`. Run `node tools/feedback-bot/register.mjs` once and run `node tools/feedback-bot/server.mjs` for the service. Local validation is `node --test tools/feedback-bot/roadmap.test.mjs`.
4. Run `/roadmap-approve` inside a forum post. Write a short summary, impact, priority and concrete acceptance criteria using no personal details. A roadmap PR is queued. Check and merge the PR. `/roadmap-status` proposes changes after the entry exists on main. For Released, verify the live Roblox build, then publish a GitHub release whose body references the exact roadmap ID and provide its tag. The bot verifies the GitHub release reference. Rejection does not modify the roadmap.

Approved entries are versioned under `docs/roadmap/feedback/`. The Dev Hub mirrors those files at save time. Approvals do not push to main, deploy Roblox changes, or publish Dev Hub versions. To recover queued jobs, restore the SQLite volume and restart. After repeated failures, inspect the named job and GitHub branch, resolve the underlying issue, then issue the command again if no successful PR exists.
